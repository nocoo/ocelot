# 01 · 产品与工程约定

状态：**需求已确认；本地实现与验收完成，生产部署待配置**

更新：2026-09-11

## 产品目标

Ocelot 是部署于 Cloudflare Workers、由 Cloudflare Access 保护的单用户
Obsidian 阅读应用。用户可以添加 GitHub 上的公开或私有仓库，浏览目录并阅读
笔记与附件。用户已说明：私有仓库主要集中在一个 GitHub 用户名下。

源仓库始终只读。应用可以记录仓库列表、阅读偏好、阅读位置和缓存状态，
不提供笔记编辑、重命名、拖拽移动、提交或推送功能。

用户已接受 PAT、定期轮换与本地 mock，并授权实现。本轮交付本地阅读应用和
可部署的生产入口；真实凭据、远程资源与 Access 域名的上线验证尚未进行。

## 阅读兼容性

已只读检查 `../obsidian` 的仓库约定与文件特征。本公开仓库只记录功能需求，
不复制私人笔记正文、文件清单或标题。

- 保留中文、空格、括号等真实 Git 路径；编码只发生在 URL 边界。
- 展示实际目录树，同时尊重 frontmatter、首个 H1 与双链表达的笔记含义；
  不根据文件夹猜测笔记类型。
- 支持 Markdown/GFM、frontmatter、普通相对链接、wikilink、别名与嵌入。
- 处理附件和相对图片路径；支持 Mermaid、callout、表格、代码块与数学公式。
- 双链需要定义路径优先级、重名歧义、标题/块锚点和缺失目标的交互。
- `.obsidian`、隐藏配置、回收站及内部自动化文件默认不进入阅读目录；
  排除规则作用于 API 和缓存读取，不能只在 View 隐藏。
- 附件不作为笔记。读取源内容时不修改原始文本或 Tolaria 管理字段。
- 导航后展开到所选文件；同篇文章应用更新时保留目录展开状态和滚动位置。
  新文章从顶部开始，指定锚点时定位目标；首版不跨刷新保存阅读位置。

已通过合成样例逐项验收，明确的容量与兼容性边界见 05；不以本地样例替代
所有真实 Obsidian 插件格式的兼容性保证。

## 三个参考系统的职责

| 参考 | 在 Ocelot 中的用途 | 已核验事实 |
| --- | --- | --- |
| Basalt | 应用外壳、侧栏、工具栏、表单、弹层、状态控件 | React 19；提供 standalone CSS 与布局组件 |
| [Kami](https://github.com/tw93/Kami) | 中英文长文排版、字体回退、层级、段落节奏与留白 | MIT 文档设计系统和模板，并非 Markdown 渲染 SDK |
| [Pierre Trees](https://github.com/pierrecomputer/pierre/tree/main/packages/trees) | 文件树、键盘导航、路径状态与变更标记 | `@pierre/trees/react`；Shadow DOM；提供主题 CSS 变量 |

Kami 的印刷配色偏暖，而 Ocelot 已明确采用冷蓝灰。适配时保留其排版原则，
按 Ocelot 主题重新映射颜色与屏幕阅读尺寸。其默认中文字体包含使用范围限制；
实际集成采用许可明确的字体或系统回退，随资源保留许可证。

Pierre 的目录树只开放选择、展开、搜索与读取行为。关闭修改、移动与拖放写入
相关能力，通过公开主题变量映射 Basalt tokens，避免依赖内部 Shadow DOM。

## 视觉方向

状态：**色板与交互已实现；明暗、移动端截图与 axe 验证通过**。

- 冷峻蓝灰用于强调色、选中态和焦点；阅读纸面与大面积背景保持干净的低彩度。
- 用有明确间隔的明度区分页面、导航和正文，不叠加多层半透明灰制造层次。
- 正文、次要说明、未选中项和 disabled 各有语义 token；disabled 不能与普通
  未选中状态混淆，也不能仅靠降低整块控件透明度表达。
- 明暗主题均验证正文对比度、键盘焦点与选中态；正文至少满足 WCAG AA。
- 阴影只用于必要的浮层层级；正文依靠排版与留白组织内容。
- 动效服务于切换、展开和反馈，避免移动正在阅读的正文；支持 reduced motion。
- 更新提示区分“正在检查”“发现新版本”“已是最新”“检查失败/受限”，
  不把“最近检查过”误写成“仓库刚更新”。
