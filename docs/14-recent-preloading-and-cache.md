# 14 · 最近更新预加载与会话缓存

状态：**已实现并通过本地验收；生产交付以对应 main 提交的 CI/CD 为准** · 2026-09-13

## 用户要求

“最近更新”每次打开等待较长；希望站点更新后提前加载，在下一次刷新之前使用缓存。

本轮将“更新”落实为知识库同步得到的新 commit：打开知识库后提前加载；发现待应用
版本后提前准备该版本，应用更新时切换。浏览器整页刷新重新建立会话，但复用 Worker
已有的私有 R2 结果。构建任务不读取运行时登记的知识库。

## 已查明的现状

- `ReaderViewModel.load()` 仅在 README 首页触发加载；从普通文章进入要等点击
  “最近更新”才开始逐批请求 GitHub 提交历史。
- 当前列表只保存在活动快照的 ViewModel 状态中，切换知识库会丢弃；发现待应用
  快照时没有预加载，应用后才重新请求。
- Worker 已按仓库 ID、算法版本和 commit 保存批次及完整结果；完整命中无需再
  扫描 GitHub。该缓存不随站点部署失效，继续复用 document 13 的实现。

## 本轮实施决定

以下为在用户授权范围内选定的实现方案，完成状态以验证记录为准。

1. 在现有 API service 中集中读取完整分页列表，以“仓库 ID + commit”保存本次
   会话的结果与进行中的 Promise；预加载、首页和弹窗共享同一次扫描。只缓存完整
   排名，空列表也是有效结果；失败可重试，不缓存失败或半成品。
2. ViewModel 激活任何快照后独立加载列表，包括普通文章、附件和空知识库；不阻塞
   文章显示。检查到待应用的新快照就后台预加载，仍展示当前阅读版本的列表；应用时
   同步使用已准备的结果，尚未完成则等待同一次请求。
3. 同一 commit 下重复打开、文章导航、知识库来回切换和无变化的更新检查都复用
   内存缓存。新 commit 单独计算，包括 tree 不变而历史改变的情形；旧响应不能覆盖
   当前阅读版本。切换知识库允许后台扫描完成，卸载页面及移除仓库取消相应任务并
   清理缓存。
4. 不增加依赖、持久浏览器存储、队列或定时扫描。私有列表仍只在浏览器内存和私有
   R2 中保存；HTTP 继续 `private, no-store`，Worker 缓存读取仍先校验 Access、
   仓库登记及 GitHub 授权。缓存未完成时立即打开仍需等待剩余扫描时间。

## 验证记录

已完成实现：API service 负责完整列表的分页、缓存和请求去重；ViewModel 负责快照
激活、待应用版本预加载、显示状态和清理时机。未改动 View、Worker API 或 R2 格式。

### 请求次数与浏览器验收

Playwright 从普通文章深链接打开合成的大知识库，清空该仓库的服务端缓存后实测
下列请求次数（仅统计该知识库）：

| 操作 | 新增最近更新 HTTP 请求 | 新增 GitHub 历史查询 |
| --- | --- | --- |
| 首次后台准备完整排名 | 12 | 12 |
| 重复打开、文章导航、知识库来回切换 | 0 | 0 |
| 整页刷新，读取已有完整结果 | 1 | 0 |

检查到待应用版本后完成预加载，旧预览仍保持原顺序；应用更新并打开完整列表不会
再发最近更新请求。重命名/删除结果与文章导航正确，首页预览和弹窗共享同一结果。
请求计数附件名为 `recent-cache-requests`，保存在 Playwright HTML 报告中。

**41 项浏览器流程通过**（38 Chromium、3 WebKit mobile），包含既有阅读、移动
导航、权限与可访问性回归。桌面及 320px 手机最近更新截图已查看，相关 axe 检查
无违规。报告及合成截图由 CI `browser-verification` artifact 保存。
